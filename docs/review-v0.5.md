## 1. 결론

0.5.0은 기존의 재생 안정화와 배포 기반 위에 실제 사용자 설정과 곡 정보 표시를 확장한
기능 릴리스다. 앨범 아트·청취자 수, 로그인 자동 실행, 시작 시 자동 재생 선택,
신버전 알림, 트레이 왼쪽 클릭 동작 선택이 하나의 설정 화면에 통합되었다.

동시에 mpv 탐색을 단순 파일 존재 확인에서 실행 가능성 검사로 강화하고, 배포 빌드가 사용할
mpv 버전과 검증 정책을 명시했다. 소스 수준 품질 게이트는 통과했지만, 최종 릴리스 판정에는
Windows 설치 프로그램과 macOS DMG를 실제로 빌드한 뒤 클린 환경 스모크를 완료해야 한다.

설정 페이지는 macOS의 비대칭 native layout-item margin을 제거해 좌우 여백을 동일하게
맞췄다. 신버전 알림 옵션은 트레이 클릭 동작 콤보박스 바로 아래에 배치한다.

### 메타데이터와 재생 안정성

- `Unknown`, 공백, 고아 구분자를 정리해 곡명이 `- title`처럼 표시되는 문제를 방지한다.
- API의 개별 artist/title이 비었으면 `Artist - Title` 형식의 text 필드에서 복구한다.
- mpv가 IPC 연결 전에 종료되면 시작 타임아웃까지 기다리지 않고 종료 코드를 보고한다.
- 재생 시작 실패를 worker에서 앱으로 전달해 재생 요청 상태를 해제하고 팝업·트레이 오류로 표시한다.
- 사용자의 일시정지 의도와 스트림의 일시적인 종료 상태를 분리해 불필요한 자동 재생을 막는다.

### 0.4.x에서 이어진 UX 개선

- Windows/macOS용 앱·트레이 아이콘과 재생 상태 표현을 정리했다.
- macOS 팝업의 첫 클릭, 바깥 클릭 닫기와 아이콘 기준 위치 결정을 안정화했다.
- 통합 오류 아이콘 점멸과 일시정지 의도 보존을 적용했다.
- 버전 태그 기반 GitHub Actions 릴리스 파이프라인과 Finder 버전 동기화를 갖췄다.

## 3. 구조 리뷰

| 영역 | 책임 | 평가 |
|------|------|------|
| `app.py` | UI·metadata·player·설정 작업 조정 | 기능 집중도가 높아졌지만 신호 기반 비동기 경계는 명확함 |
| `ui/popup.py` | 재생/설정 페이지와 반응형 높이 | 단일 팝업 UX를 유지하면서 설정을 자연스럽게 수용 |
| `startup.py` | OS별 사용자 로그인 시작 등록 | 플랫폼 차이를 작은 모듈로 격리 |
| `updates.py` | GitHub 릴리스 조회·버전 비교 | 네트워크 코드와 UI 결정을 분리 |
| `metadata/client.py` | API 정규화와 stream 선택 | 불완전한 실제 metadata에 대한 방어 강화 |
| `paths.py`, `mpv_player.py` | mpv 후보 순서와 실행 검증 | 개발 환경과 frozen 배포 정책이 분명해짐 |

앨범 아트와 릴리스 조회는 Python background thread에서 수행하고 Qt signal로 메인 스레드에
결과를 전달한다. UI 객체를 작업 스레드에서 직접 조작하지 않는 점은 적절하다. 다만 기능이
계속 늘어난다면 다음 버전에서는 `CodeRadioApp`의 artwork/update/settings 책임을 별도 서비스로
분리하는 것이 유지보수에 유리하다.

## 4. mpv와 배포 재현성

개발 환경의 mpv 탐색 순서는 다음과 같다.

1. 사용자가 지정한 `mpv_path`
2. 현재 `PATH`에서 찾은 실행 파일
3. 저장소의 `.tools/mpv/extract` 캐시

frozen 릴리스는 시스템 설치를 사용하지 않고 앱에 번들된 mpv만 찾는다. 모든 후보는
`mpv --version`을 5초 제한으로 실행해 실제 사용 가능 여부를 확인한다.

`packaging/mpv-versions.json`은 다음 빌드 입력을 고정한다.

- Windows: archive 이름·URL·버전·SHA256
- macOS: Homebrew formula 이름과 formula revision

Windows 다운로드는 SHA256과 캐시 marker를 확인하고, macOS 빌드는 설치된 formula revision과
실행 가능성을 검사한다. 이는 예기치 않은 최신 바이너리 혼입을 막지만, Homebrew가 고정한
revision보다 앞서가면 과거 revision을 쉽게 설치할 수 없다는 운영 위험이 있다. mpv 정책을
올릴 때는 양 OS 빌드와 클린 실행을 함께 검증해야 한다.

## 5. 설정·업데이트 동작 검토

- 기존 config에는 새 필드가 없어도 dataclass 기본값이 적용되므로 마이그레이션 파일이 필요 없다.
- 설정 값은 clamp를 거쳐 boolean과 허용된 tray action으로 정규화된다.
- 로그인 시작 등록에 실패하면 UI 설정을 이전 값으로 되돌리고 상태 문구를 표시한다.
- 업데이트 확인은 옵션이 켜진 경우 시작 1.5초 뒤 실행하며 중복 요청을 막는다.
- 새 버전 알림을 클릭하면 해당 GitHub Release 페이지를 연다.
- 버전 비교는 `v0.5.0`과 `0.5.0`을 모두 처리하고 숫자 구성요소로 비교한다.

현재 업데이트 기능은 알림과 다운로드 페이지 연결만 제공한다. 바이너리를 자동 다운로드하거나
설치하지 않으므로 코드 서명되지 않은 앱에서 불필요하게 위험한 자동 교체 경로를 만들지 않는다.

## 7. 잔존 위험과 릴리스 게이트

| 등급 | 항목 | 대응 |
|------|------|------|
| High | 0.5.0 OS별 배포 산출물 미검증 | Windows setup과 macOS DMG를 빌드하고 클린 설치·재생 확인 |

| Low | GitHub API 또는 artwork 서버 장애 | 앱 동작 유지, 상태 문구 또는 플레이스홀더로 degrade |
| Low | Linux 데스크톱별 tray 차이 | best-effort 정책과 별도 문서 유지 |

## 8. 최종 평가

0.5.0은 0.3의 단독 배포 기반과 0.4의 플랫폼 UX 안정화를 바탕으로, 초기 설계에서
MVP 이후로 분류했던 앨범 아트·청취자 수·로그인 자동 시작을 실제 제품 기능으로 완성했다.
사용자 선택권과 오류 가시성도 함께 개선되어 기능 수준에서는 0.5.0으로 묶기에 충분하다.

현재 판정은 **“소스 품질 게이트 통과, 배포 게이트 대기”**다. OS별 산출물과 로그인 사이클을
검증한 후 `v0.5.0` 태그를 생성하는 것이 적절하다.
